# Benchmark 报告

## 1. 环境

- 日期：2026-10-07
- CPU：Intel(R) Core(TM) i7-14650HX
- 操作系统：Windows
- 编译器：g++ 8.1.0 (MinGW-w64)
- 构建模式：Release，-O3 -DNDEBUG
- 矩阵大小：1024 x 1024
- 基准程序：benchmarks/bench_matmul.cpp
- 测量方法：同一个进程内交替执行 i-j-k 和 i-k-j，共 20 轮，统计每轮比值的中位数

## 2. 早期顺序测量为什么不可信

第一次顺序测量得到 1.357 倍：

```text
i-j-k  median: 78.855 ms
i-k-j  median: 58.1299 ms
```

这是错的。

原因：机器性能是双峰的，会从快峰跳到慢峰。
顺序测量可能把 i-j-k 的快峰和 i-k-j 的慢峰放在一起比。

## 3. 多次独立复现

同一个 `bench_matmul.exe`，不同时间/环境下结果如下：

| 运行者 | i-j-k median | i-k-j median | speedup |
| --- | --- | --- | --- |
| 用户正常终端 | 2590.87 ms | 182.018 ms | 13.8813x |
| 助手沙箱环境 | 5064.03 ms | 856.932 ms | 5.883x |
| 总指挥第 1 次 | 4204.61 ms | 833.98 ms | 5.02x |
| 总指挥第 2 次 | 4761.55 ms | 860.28 ms | 5.76x |
| 总指挥第 3 次 | 4460.9 ms | 866.25 ms | 5.16x |

checksum 全部一致：

```text
10708.4
```

说明数值正确性没有问题。

## 4. 结论：13.8813x 是快峰窗口，不可作为稳定结论

- 用户正常终端那次 `i-k-j = 182 ms`，是撞上了极快的窗口；
- 助手沙箱和总指挥的三次复现都落在慢峰附近，speedup 约 5.0 到 5.9 倍；
- 这台机器会在快峰和慢峰之间跳，而且 `i-k-j` 对慢状态更敏感，所以比值会明显变化。

可信结论应写成：

```text
1024 x 1024 matmul，稳定环境下约 5 倍加速；
在极快的窗口里可以观察到约 14 倍，但不能作为稳定结论。
```

更保守、更可复现的说法是：

```text
优化后至少约 5 倍加速。
```

## 5. 为什么快

- 矩阵在内存里是行优先连续存放的；
- i-j-k 的最内层变化的是 k，访问 B[k][c] 时地址按列跳动，空间局部性差；
- i-k-j 的最内层变化的是 c，访问 B[k][c] 和写 C[r][c] 都连续按行进行；
- 连续访问更容易命中 cache，减少去内存取数据的次数，所以更快。

## 6. 正确性验证

- 优化后 `ctest`：11/11 全部通过；
- benchmark checksum 多次一致：10708.4；
- 数值逐元素一致，无精度损失。

## 7. 结论

- [x] 优化前基线已建立；
- [x] 优化后数字已重测；
- [x] benchmark 程序可以复现两个版本对比；
- [x] 识别出机器双峰问题；
- [x] 稳定可复现结论：至少约 5 倍加速；
- [x] 能解释 i-k-j 为什么对 cache 更友好。

## 8. 第二步：inline at()

问题：at() 原先只有声明，定义在 src/tensor.cpp，跨 TU 调用无法内联。

改前对照（总指挥）：

```text
at()      8908.61 ms
裸指针     770.378 ms
约 11.6 倍
```

改法：把 rows/cols/size/shape/at 的实现移到 tensor.hpp，使其可内联；并从 src/tensor.cpp 删除旧定义。

改后实测（用户正常终端，1024x1024，20 轮交替）：

```text
at_ikj median: 146.641 ms
ptr_ikj median: 150.677 ms
median per-round ratio: 0.972715x
checksum: 10708.4
```

说明：
- inline 后，at() 版本和裸指针版本已经同速；
- ratio 约 0.97 到 1.00，属于测量噪声；
- 跨 TU 函数调用开销已消除；
- checksum 不变，正确性没问题。
