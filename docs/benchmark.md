# Benchmark 报告

## 1. 环境

- 日期：2026-10-04
- CPU：未记录
- 操作系统：Windows
- 编译器：g++ 8.1.0 (MinGW-w64)
- 构建模式：Release，-O3 -DNDEBUG
- 矩阵大小：512 x 512
- 基准程序：benchmarks/bench_matmul.cpp

## 2. 原始顺序测量（无效对比）

第一次测量结果：

```text
i-j-k  median: 78.855 ms
i-k-j  median: 58.1299 ms
```

按这两个中位数计算得到：

```text
1.357 倍
```

但这个数字是错的。

原因：这台机器性能呈双峰分布，测量结果会在快峰和慢峰之间跳。
第一次测量把 i-j-k 的快峰结果和 i-k-j 的慢峰结果放在一起比，属于系统性测量错误。

## 3. 受控实验（总指挥复现）

方法：

- 在同一个进程里交替执行两个版本；
- 各跑 20 次；
- 避免一个版本先跑、另一个版本后跑的热状态差异；
- 按同一轮内的 i-j-k / i-k-j 计算加速比。

结果：

| 版本 | 前几轮 | 后几轮 | 分布 |
| --- | --- | --- | --- |
| i-j-k | 376, 362, 366, 355, 353 ms | 960, 1081, 1013, 962, 1037, 1035, 1106, 1084, 1095, 1098, 1128, 1084, 1078, 1056, 1071 ms | 双峰：约 360 ms 与约 1060 ms |
| i-k-j | 51, 50, 52, 50, 59 ms | 151, 141, 154, 117, 137, 144, 169, 139, 158, 166, 151, 142, 163, 162, 155 ms | 双峰：约 50 ms 与约 150 ms |

关键：

- 每个版本内部都是双峰的，说明波动来自机器，不是代码；
- 加速比在两种状态下都稳定：
  - 快峰对快峰：353 / 49.5 约等于 7.1 倍
  - 慢峰对慢峰：1037 / 142 约等于 7.3 倍

因此可信结论是：i-k-j 相比 i-j-k 约快 6.4 到 7.3 倍。

## 4. 正确性验证

- 优化后 ctest：10/10 全部通过；
- benchmark checksum 不变：1257.88；
- 数值逐元素一致，没有精度损失。

## 5. 为什么快

- 矩阵在内存里是行优先连续存放的；
- 原来的 i-j-k 写法中，最内层变化的是 k，访问 B[k][c] 时地址按列跳动，空间局部性差；
- 改成 i-k-j 后，最内层变化的是 c，访问 B[k][c] 和写 C[r][c] 都连续按行进行；
- 连续访问更容易命中 cache，减少去内存取数据的次数，所以更快。
